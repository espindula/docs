Assunto: GNU nano


====================
====================


Invocar o editor estabelencendo a quebra automática de linha em dez 
caracteres:

$ nano --fill=10 /tmp/teste.txt


Obs.: no ambiente Debian GNU/Linux 8 (Jessy), ao examinar-se o arquivo 
</etc/nanorc> original (conforme instalado pela distribuição e sem 
qualquer personalização), constata-se (linha 94) que a funcionalidade de 
quebra automática de linha foi _desabilitada_ (set nowrap).   Em tal 
Sistema Operacional, portanto, apenas via linha de comando é que se 
consegue o efeito da quebra automática de linhas (sem alterar o 
arquivo de configuração evidentemente).

Incluído em: segunda-feira, 13 de setembro de 2021.


Diferença entre "softwrap" e "breaklonglines"


1 - "softwrap" ("quebra flexível de linhas longas") (exibe várias colunas na mesma linha)

Meta + S: ou habilita ou desabilita

"softwrap": se atingir a borda direita da tela, então _aparenta_ ocorrer uma quebra de linha. Só aparenta. O texto continua _na mesma linha_. Contendo ou não espaços em branco, o texto continua _na mesma linha_. Por exemplo, esta linha aqui fica visível toda na tela, mesmo sendo "mais larga" em termos de caracteres. Mesmo escrevendo-se mais que _trezentos caracteres_, ainda assim, o GNU Nano mantém _todo o texto na mesma linha_. Linha bastante longa! Por que alguém desejaria escrever uma linha gigantesca (com mais que trezentos, quinhentos, caracteres!)?


2 - "breaklonglines" ("quebra rígida de linhas longas")

Meta + L: ou habilita ou desabilita



"breaklonglines": se atingir a borda direita da tela, então efetivamente ocorre uma quebra de linha. O texto continua _em outra linha_.

Conclusão um: se for habilitar "breaklonglines", então desabilitar "softwrap". Explicação: não faz sentido a "quebra flexível de linhas longas" quando já se tem a "quebra rígida de linhas longas" habilitada.

Conclusão dois: se for habilitar "softwrap", então habilitar "atblanks".

Conclusão três: se for habilitar "breaklonglines", então definir "fill".

Conclusão quatro: se habilitar "breaklonglines" já dentro de uma sessão do nano, então o "fill" será definido para o padrão (-8) ou o valor que estiver definido no arquivo de controle de execução (nanorc).

Conclusão cinco: concorda-se com a configuração do "fill" sugerida no projeto "Linux From Scratch": (set fill 72).

Conclusão seis: é mais conveniente e oportuno habilitar "breaklonglines" já dentro de uma sessão do nano (com o "fill" já previamente definido no arquivo de controle de execução [nanorc]).


GNU nano - Bugs: bug #49959: [Request] do softwrap at word boundaries instead of at screen's edge. Disponível em: <https://savannah.gnu.org/bugs/?49959>. Acesso em: 13 set. 2021.

Dispositivo: computador CCE (comp02)
Sistema Operacional: Debian GNU/Linux 12 ("bookworm")


Saída gerada pelo comando <echo "${COLUMNS}">:

113


 = = = = = Transcrição inicia = = = = =

## Set the target width for automatic hard-wrapping and for justifying
## paragraphs.  If the specified value is 0 or less, the wrapping point
## will be the terminal's width minus this number.
#set fill -8

 = = = = = Transcrição termina = = = = =

Fonte: arquivo </etc/nanorc> instalado com a distribuição.

Tradução: Configura a largura alvo para "quebra rígida de linhas longas" 
e para justificamento de parágrafos. Se o valor especificado for 0 ou 
menos, o ponto de quebra será a largura do terminal menos esse número.

Saída gerada pelo comando <echo $(( "${COLUMNS}" - 41 ))>:

72

Conclusão: para a distribuição Debian GNU/Linux, deve-se configurar 'set 
fill' para o valor '-41' para se obter uma "quebra rígida de linhas 
longas" no caractere de número 72.

Problema: como eliminar espaços em branco no início de linhas:


Passo um: acessar o recurso de substituir: Ctrl + \

Passo dois: ativar o modo de expressão regular: Esc + R

Passo três: expressão de busca: "^ +"

Passo quatro: expressão de substituição: nada
